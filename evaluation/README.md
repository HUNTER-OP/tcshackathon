# Hisab Kitab: Evaluation Evidence

The model, the datasets and the metrics are all in this folder. Every number here was produced by the scripts named below, and the `terminal_outputs/` folder holds their actual console output. Generated 2026-10-28.

## Headline results

| What | Test set | Result | Target |
|---|---|---|---|
| End-to-end query resolution, cloud (hybrid) | 200 held-out questions | **87.5%** | ≥ 80% |
| End-to-end query resolution, offline (Ollama)* | 200 held-out questions | **88.5%** | ≥ 80% |
| Response time p50 / p95 / max (hybrid) | same 200 | **1.37 s / 5.84 s / 14.4 s** | p95 < 15 s |
| Language detection accuracy | same 200 | **99.5%** | — |
| Intent model alone: accuracy / macro-F1 | 200 held-out questions | 85.5% / 0.829 | — |
| Intent model alone: accuracy / macro-F1 | 1,522-row internal test split | 96.1% / 0.962 | — |
| Automated tests | `backend/tests` | **96 passed** | — |

\* The offline run was done before the final profanity cleanup and retraining. The hybrid run uses the final model.

**Why end-to-end beats the model alone (87.5% vs 85.5%):** the chat pipeline adds a translate-and-retry step when the model is unsure about a Hindi, Kannada or Hinglish message. It also handles sensitive-information questions and button confirmations with fixed rules.

**Which test set to trust:** the 200 held-out questions were written separately, and any similar sentence was removed from training. They're the honest benchmark. The internal split is easier, because it comes from the same sources as the training data.

## Where each number is calculated

| Step | Script | Command (from `D:\Hisab_kitab`) | Output here |
|---|---|---|---|
| 1. Build the training set | `backend/app/ml/build_dataset.py` | `cd backend && ..\.venv\Scripts\python -m app.ml.build_dataset` | `terminal_outputs/01_build_dataset.txt` |
| 2. Train the intent model (GPU) | `backend/app/ml/train_intent.py` | `cd backend && ..\.venv\Scripts\python -m app.ml.train_intent` | `terminal_outputs/02_train_intent_metrics.json` |
| 3. Classification report, confusion matrix and per-language metrics | `eval/metrics_report.py` | `.venv\Scripts\python eval\metrics_report.py` | `terminal_outputs/03_metrics_report.txt` and `metrics/` |
| 4. End-to-end evaluation (full chat flow with the LLM) | `eval/run_eval.py` | `.venv\Scripts\python eval\run_eval.py --mode hybrid` (or `--mode local`) | `terminal_outputs/04a_*.txt`, `04b_*.txt`, `metrics/results_*.json` |
| 5. Automated tests | `backend/tests/` | `.venv\Scripts\python -m pytest backend\tests -m "not live" -v` | `terminal_outputs/05_pytest_96_tests.txt` |

Step 3 uses scikit-learn's `classification_report` and `confusion_matrix`. Step 4 counts a question as **resolved** when all of these hold:
- the intent is correct
- the reply isn't empty
- any required phrase is present; for example, the no-consent customer must get a consent message

## `metrics/`

| File | Contents |
|---|---|

| `heldout_200_confusion_matrix.csv` / `.png` | 17×17 confusion matrix: rows are the true intent, columns the predicted one |

## `datasets/`

All data is public or synthetic. No real customer data is used.

| File | Rows | Source / purpose |
|---|---|---|
| `raw/banking77_train.csv`, `raw/banking77_test.csv` | 10,003 / 3,079 | [Banking77](https://github.com/PolyAI-LDN/task-specific-datasets) (PolyAI, CC-BY-4.0): real-style banking queries, 77 intents mapped to our 17 |
| `raw/bitext_banking.csv` | 21,895 | [Bitext Retail Banking](https://huggingface.co/datasets/bitext/Bitext-retail-banking-llm-chatbot-training-dataset): 26 intents. 3,650 deliberately offensive variants were removed. |
| `processed/llm_paraphrases.jsonl` | 1,400 | Natural paraphrases in English, Hindi, Kannada and Hinglish, generated by Gemini, Groq and Ollama (`backend/app/ml/augment_llm.py`) |
| `processed/intent_train.jsonl` | 11,164 | Final training set: Banking77 and Bitext (capped at 600 per intent) + multilingual templates + paraphrases. Profanity-filtered. |
| `processed/intent_test.jsonl` | 1,522 | Internal test split, the 12% held out from the same pool |
| `test_sets/heldout_200_queries.jsonl` | 200 | Independent test set: 50 per language, covering all 17 intents |
| `bank/customers.csv`, `accounts.csv`, `cards.csv`, `loans.csv`, `transactions.csv` | 50 / 67 / 94 / 13 / ≈8,600 | Synthetic bank: Faker en_IN with seed 42, masked numbers and consent flags (`backend/app/seed.py`) |
| `bank/products.json` | — | Rates, loans with eligibility rules, fees, FAQ |
| `bank/query_logs.txt`, `.jsonl` | 5,000 | Synthetic customer query logs in text format, as the brief asks. Illustrative only. |

**Training set by language:** English 8,249, Hindi 973, Kannada 940, Hinglish 1,002.

**Model:** `distilbert-base-multilingual-cased`, fine-tuned for 4 epochs on an RTX PRO 4000 Blackwell in about 34 s, with bf16 precision, batch size 64 and learning rate 5e-5. Inference takes about 3–8 ms per query on the GPU.

## Known weak spots (from the held-out confusion matrix)

| Intent | Held-out F1 | What goes wrong |
|---|---|---|
| general questions (`faq_general`) | 0.53 | "Good morning" and similar greetings are predicted as `spending_summary` |
| `transfer_money` | 0.62 | Some transfer-status questions are predicted as `dispute_refund` |
| `dispute_refund` | 0.64 | Recall is 1.0 but precision is 0.47: it absorbs other complaint-like messages |
| `card_activate` | 0.67 | "Switch on my new card" is predicted as `card_block` or `card_issue` |
